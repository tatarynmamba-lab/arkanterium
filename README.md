# Аркантериум

Тёмный бизнес-каталог с фиолетовыми акцентами, личными аккаунтами и страницами бизнесов.

**Работающий сайт:** https://arkanterium-workspace.wirybuddy.chatgpt.site

Эту ссылку можно отправить другу. Он открывает «Личный кабинет» → «Создать аккаунт», указывает имя, придумывает логин и пароль. **Аккаунт ChatGPT не нужен.** После регистрации нужно сохранить резервный код восстановления и перейти в свой профиль. Личные заметки, файлы, фотографии профиля и черновики доступны только их владельцу. Бизнесы становятся видны в каталоге после публикации.

Этот архив дополнительно содержит **самостоятельную серверную версию** с регистрацией по логину и паролю, без зависимости от ChatGPT. Её можно загрузить в GitHub и запустить на своём компьютере или сервере. Данные самостоятельной установки и работающего сайта по ссылке выше хранятся отдельно. Архив не содержит ваши пароли, пользователей, личные материалы или базы данных.

## Личный аккаунт администратора на работающем сайте

Логин владельца: **insaf_admin**. Пароль отсутствует в этом архиве и не публикуется в переписке.

1. Владелец открывает https://arkanterium-workspace.wirybuddy.chatgpt.site/admin-setup.html .
2. Если потребуется, один раз подтверждает, что он владелец сайта, через свой прежний вход. Эта проверка доступна только владельцу и не создаёт обычные аккаунты.
3. Страница создаёт новый случайный пароль прямо в браузере. Владелец может оставить его или придумать свой.
4. После активации нужно скачать личный файл с логином, паролем и резервным кодом. **Этот личный файл нельзя загружать в GitHub или пересылать другим.**
5. Дальше используется обычный вход по логину `insaf_admin` и установленному паролю.

Новые участники выбирают свой логин и пароль через «Создать аккаунт». Они получают обычные права; регистрация не выдаёт права администратора. Вход прежних аккаунтов после сброса отключён. Категории каталога сохраняются.

Эта страница активации относится к работающему сайту по ссылке выше. Для отдельной серверной установки администратор создаётся командой `npm run admin:create`, описанной ниже.

## Общение и оформление

- **Лента сообщества** открывается из главного меню и личного кабинета. Это настоящая общая лента: публикации, комментарии и отметки «Нравится» сохраняются на сервере и появляются у других посетителей. Обновление происходит примерно раз в 5 секунд.
- Ленту читают все посетители; писать можно после входа. Автор может изменить и удалить свою запись. Администратор может удалить чужую публикацию или комментарий, но не подменить текст автора.
- На странице профиля нажмите **«Изменить фон»**: доступны 8 цветовых вариантов и собственное изображение JPG, PNG или WebP до 8 МБ.
- На странице своего бизнеса нажмите **«Изменить фон»** в панели владельца. После сохранения фон опубликованного бизнеса видят его посетители. Фон черновика остаётся доступен владельцу.
- Настройки хранятся на сервере; другой пользователь не может поменять ваш фон. Цветовой фон и фотографии не раскрывают личные файлы аккаунта.

## Восстановление доступа на работающем сайте

Нажмите «Забыли пароль?», введите логин, сохранённый резервный код и новый пароль. Старый код перестанет действовать: сохраните новый код, показанный на экране. Все прежние сеансы будут завершены. Без пароля и резервного кода автоматического восстановления нет; письма для сброса пароля пока не отправляются.

## Что уже работает

- Один список разделов в главном меню. Нажатие открывает карточки бизнесов выбранного раздела.
- Поиск по названию и описанию, фильтр города, сортировка. На главную ведёт название «Аркантериум» слева сверху.
- Регистрация по логину и паролю, вход и выход на работающем сайте и в самостоятельной версии.
- Отдельный личный профиль: имя, описание, аватар, обложка, фотографии, записи, закрепление и комментарии к собственным записям. Профиль сохраняется на сервере и доступен с разных устройств после входа.
- Личные заметки и файлы. Другие аккаунты их не видят.
- Карточки бизнесов и отдельные страницы: описание, контакты, логотип, обложка, галерея, записи, черновик и публикация.
- Администратор меняет названия, описания, порядок и иконки разделов, добавляет новые разделы и модерирует ленту.
- Общая лента с комментариями и отметками «Нравится».
- Индивидуальные фоны профиля и каждой страницы бизнеса, включая загрузку изображений.
- Более яркая главная страница с фиолетовыми, сиреневыми и розовыми акцентами.

Общая лента — публичное общение между участниками. Личная переписка один на один пока не реализована. Личные профили, заметки и файлы закрыты от других пользователей; общедоступны лента и опубликованные страницы бизнесов.

## Самый простой способ поделиться через GitHub

1. Распакуйте ZIP. Внутри откройте папку `arkanterium-github`.
2. Создайте пустой репозиторий на GitHub.
3. Выберите **Add file → Upload files** и загрузите содержимое папки. Загружать сам ZIP вместо файлов не нужно.
4. Сохраните изменения кнопкой **Commit changes**.
5. Другу можно отправить ссылку на репозиторий: в начале этой инструкции есть ссылка **«Работающий сайт»**.

Если нужна именно ссылка вида `имя.github.io/репозиторий`:

1. В репозитории откройте **Settings → Pages**.
2. В **Build and deployment** выберите **Deploy from a branch**.
3. Выберите ветку **main**, папку **/(root)** и нажмите **Save**. Если у вас уже выбрана **/docs**, она также поддерживается.
4. Дождитесь появления адреса страницы. Отправьте этот адрес другу.

Файлы `index.html` в корне и `docs/index.html` содержат страницу перехода на работающий Аркантериум. Корневой `index.html` позволяет открывать сайт вместо README при настройке GitHub Pages «main / (root)». Это ссылка-переход: данные и авторизация обслуживаются работающим сайтом, а не GitHub Pages. После самостоятельного развёртывания вы можете заменить адрес в обоих файлах `index.html` и `docs/index.html` на адрес своего сервера.

**GitHub Pages обслуживает статические страницы и сам не запускает Node.js-сервер с аккаунтами и базой данных.** Поэтому для независимой версии используйте запуск ниже. Источник: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## Запустить самостоятельную версию на Windows

1. Установите **Node.js 24 LTS** с https://nodejs.org/ . После установки закройте и заново откройте терминал.
2. Распакуйте архив в обычную папку, например `C:\arkanterium`.
3. Дважды нажмите `Start-Windows.cmd`.
4. Оставьте появившееся окно открытым. Откройте **http://localhost:3000** в браузере.
5. Нажмите **«Личный кабинет → Создать аккаунт»** и задайте своё имя, логин и пароль.

Либо откройте терминал в папке с `package.json` и выполните:

```sh
npm start
```

Устанавливать дополнительные npm-пакеты для работы архива не требуется. Не открывайте HTML двойным щелчком: функции аккаунтов работают через запущенный сервер. `localhost` доступен только на вашем компьютере; отправлять этот адрес другу из другого города бесполезно.

Остановить сайт можно сочетанием **Ctrl+C** в окне сервера. При следующем запуске аккаунты и материалы сохранятся.

## Получить права администратора

Обычная регистрация всегда создаёт пользователя. Первый зарегистрировавшийся не становится администратором автоматически.

В папке проекта откройте второй терминал:

```sh
npm run admin:create
```

Введите логин. Если аккаунт уже существует, подтвердите выдачу ему прав администратора. Если он новый, команда попросит имя и пароль. Пароль при вводе скрыт. После входа откройте **«Личный кабинет → Разделы сайта»**.

Иконки и разделы публикуются кнопкой **«Сохранить разделы»**. На открытой странице каталога пользователей они обновляются автоматически.

## Как пользователь размещает бизнес

1. Войти в свой аккаунт.
2. Открыть **«Личный кабинет → Мои бизнесы → Добавить бизнес»**.
3. Заполнить название, раздел и описание. Внешний сайт необязателен.
4. Сохранить черновик или опубликовать карточку.
5. Нажать **«Перейти на страницу бизнеса»**.
6. Добавить описание, контакты, обложку, логотип, фотографии и записи.

Черновик виден только владельцу. После публикации карточка появляется в своём разделе каталога, а посетители открывают страницу бизнеса. Редактирование остаётся у владельца.

## Независимый сайт в интернете

Для серверной версии нужен сервер с постоянным диском и HTTPS. В архив включён вариант Docker Compose с Caddy. Он рассчитан на один сервер и небольшой проект.

1. Подготовьте сервер с Docker и Docker Compose, домен и его DNS-запись на IP сервера.
2. Загрузите файлы проекта на сервер, например через GitHub и `git clone`.
3. В корне проекта создайте файл `.env` с одной строкой (подставьте свой домен):

```dotenv
DOMAIN=arkanterium.example.com
```

4. Убедитесь, что сервер принимает подключения на порты 80 и 443. Выполните:

```sh
docker compose up -d --build
docker compose exec app npm run admin:create
```

5. Откройте `https://ваш-домен` и отправьте этот адрес другим людям. Здесь они регистрируются по логину и паролю. Caddy получает HTTPS-сертификат при корректном DNS и доступных портах. Условия описаны в документации: https://caddyserver.com/docs/automatic-https

Порт приложения 3000 не публикуется в интернет. Данные находятся в постоянном Docker volume `arkanterium-data`. Не используйте `docker compose down -v`: это удалит данные. Для обновления кода используйте `docker compose up -d --build`, сохраняя volume.

Если запускаете без Docker: задайте `APP_ORIGIN=https://ваш-домен`, `NODE_ENV=production`, `DATA_DIR` на постоянный диск и поставьте HTTPS reverse proxy перед Node.js. `APP_ORIGIN` должен точно совпадать с адресом в браузере, без завершающего `/`. Не включайте `TRUST_PROXY=1`, если к порту Node.js можно обращаться напрямую из интернета.

## Данные, пароли и резервные копии

- Аккаунты, сеансы и записи хранятся в `data/arkanterium.sqlite`; фотографии и файлы — в `data/uploads/`.
- Папка `data` и файл `.env` исключены из Git. Не загружайте их в публичный репозиторий.
- Пароли хранятся в виде хешей scrypt с отдельной солью. Сеансы — в HttpOnly-cookie; при HTTPS cookie имеют флаг Secure. Правила доступа проверяются сервером.
- Чтобы сделать простую резервную копию локальной установки, остановите приложение, скопируйте **всю папку `data`**, затем запустите приложение снова.
- Для Docker сохраняйте всё содержимое volume `arkanterium-data` при остановленном приложении. Копию храните отдельно от сервера.
- В самостоятельной Node.js-установке пароль восстанавливает администратор через терминал. Резервный код описан выше для работающего сайта; в отдельной установке его пока нет. Отправка писем для восстановления не подключена:

```sh
npm run password:reset
```

В Docker: `docker compose exec app npm run password:reset`. Команда также завершает прежние сеансы этого пользователя.

## Проверка и структура

```sh
npm test
```

- `content/` — страницы HTML.
- `public/assets/` — JavaScript, стили и иконки интерфейса.
- `server/` — HTTP-сервер, регистрация, хранилище и API на JavaScript.
- `migrations/` — изменения схемы базы данных; применяются автоматически при запуске.
- `scripts/admin.mjs` — управление администратором и сброс пароля.
- `index.html`, `docs/index.html` — переход с GitHub Pages на работающий сайт; поддерживают настройки публикации из корня и из `/docs`.
- `tests/` — проверки регистрации, сеансов и изоляции двух аккаунтов.

`server/api.mjs` собран из общей логики рабочего сайта без минификации. Все файлы самостоятельной версии — обычные HTML, CSS и JavaScript. Приватная база рабочего сайта и его ключи в архив не включены.
